## Подробное объяснение

### Общая структура скрипта

1. `webdriver.Chrome()` запускает браузер, а `WebDriverWait(driver, 10)` создаёт объект явного ожидания.
2. `driver.get(URL)` открывает сайт. Потом `wait.until(EC.presence_of_element_located(...))`
   ждёт строку поиска: так мы знаем, что страница отрисовалась.
3. Пять блоков по 10 локаторов. Каждый блок начинается с `print("--- ... ---")`, чтобы вывод было легко читать.
4. Проверки (`assert`): разные стратегии для одного и того же элемента должны дать **равные**
   `WebElement`. Selenium сравнивает элементы через `==` по их внутреннему id в браузере.
5. Переход на `/login`, явное ожидание поля `Email`, ещё 5 локаторов `By.NAME` и проверки.
6. `finally: driver.quit()` закрывает браузер всегда, даже если что-то упало.

### `find_element` и `find_elements`

- `find_element(By.X, "...")` возвращает **первый** подходящий элемент. Если ничего не найдено,
  бросает `NoSuchElementException`.
- `find_elements(By.X, "...")` возвращает **список**, а если ничего нет, то пустой список `[]`
  без ошибки. Этим способом мы ищем то, чего на странице несколько: карточки товаров,
  кнопки «Add to cart», radio-кнопки опроса.

### 1. By.ID

`id` по стандарту HTML уникален на странице. Поэтому это самый быстрый и надёжный локатор:
если у элемента есть id, лучше брать его.

```python
search_input = driver.find_element(By.ID, "small-searchterms")
```

Внутри Selenium `By.ID` превращается в CSS `#small-searchterms`.
Элементы `flyout-cart` и `mob-menu-button` на десктопе не видны, но `find_element` их находит:
поиск идёт по DOM, а видимость он не проверяет. Если элемент должен быть **виден**,
нужно ожидание `EC.visibility_of_element_located` или проверка `is_displayed()`.

### 2. By.CLASS_NAME

Ищет по **одному** классу из атрибута `class`.

```python
search_box_button = driver.find_element(By.CLASS_NAME, "search-box-button")
```

У кнопки поиска `class="button-1 search-box-button"`, то есть два класса.

- ✅ `By.CLASS_NAME, "search-box-button"` подходит.
- ❌ `By.CLASS_NAME, "button-1 search-box-button"` упадёт с ошибкой: пробел в имени класса недопустим.
- ✅ Для двух классов сразу пишут CSS: `By.CSS_SELECTOR, ".button-1.search-box-button"`.

Классы обычно не уникальны: `button-1` есть у двух кнопок, а `product-item` у шести карточек.
Поэтому для карточек используется `find_elements`.

### 3. Поиск по атрибуту

Отдельной стратегии `By.ATTRIBUTE` в Selenium **нет**. По любому атрибуту ищут через
CSS-селектор (или через XPath с `@атрибут`):

| Синтаксис | Значение | Пример из скрипта |
|---|---|---|
| `[attr='v']` | атрибут равен `v` | `a[href='/register']` |
| `[attr^='v']` | начинается с `v` | `a[href^='/news/rss']` |
| `[attr$='v']` | заканчивается на `v` | (например, `a[href$='/cart']`) |
| `[attr*='v']` | содержит `v` | `img[src*='logo']` |
| `[attr]` | атрибут просто есть | (например, `input[placeholder]`) |

Имя тега перед скобками (`a[...]`, `input[...]`) сужает поиск и делает локатор понятнее.
Одну и ту же кнопку поиска мы нашли по `type`, по `value` и по классу, и `assert` подтверждает, что это один элемент.

### 4. By.XPATH

XPath описывает путь к элементу в дереве документа. В скрипте 10 разных приёмов:

| Приём | Пример | Что делает |
|---|---|---|
| `//` | `//input[...]` | ищет на любом уровне вложенности |
| `/` | `//div[@class='header-logo']/a/img` | идёт к прямому потомку, шаг за шагом |
| `[@attr='v']` | `//input[@value='Subscribe']` | условие по атрибуту |
| `text()` | `//a[text()='Log in']` | точный текст узла |
| `contains()` | `//a[contains(@href,'/books')]` | атрибут или текст содержит подстроку |
| `starts-with()` | `//a[starts-with(@href,'/register')]` | атрибут начинается с подстроки |
| `(…)[N]` | `(//div[@class='item-box'])[1]` | N-й результат; **нумерация с 1**, не с 0 |
| `parent::` | `.../h3[...]/parent::div` | подняться к родителю |

Две ловушки, которые показывает скрипт:

- **`@class='…'` сравнивает строку целиком.** У блока категорий `class="block block-category-navigation"`,
  поэтому `//div[@class='block-category-navigation']` ничего **не найдёт**. Нужно писать полную
  строку или `contains(@class,'block-category-navigation')`.
- **`text()` видит HTML, а `.text` видит экран.** В HTML заголовок записан как `Categories`, а CSS
  (`text-transform: uppercase`) показывает его как `CATEGORIES`. Поэтому XPath `//strong[text()='Categories']`
  находит элемент, а `xp_categories.text` возвращает `"CATEGORIES"`. Скрипт проверяет оба факта.

`(//div[@class='item-box'])[1]` и `//div[@class='item-box'][1]` означают **разное**.
Первый вариант берёт первый элемент из всех найденных на странице. Второй берёт каждый `item-box`,
который стоит первым среди своих соседей, а таких может быть несколько.

### 5. By.NAME

Ищет по атрибуту `name`. Он есть у полей форм (`input`, `select`, `textarea`), потому что
именно по `name` браузер отправляет данные на сервер. Он есть и у тегов `<meta>` в `<head>`.

```python
name_q = driver.find_element(By.NAME, "q")
name_poll = driver.find_elements(By.NAME, "pollanswers-1")  # 4 radio-кнопки
```

Особенности:

- `name` **не обязан быть уникальным**. У всех четырёх radio опроса `name="pollanswers-1"`, и так
  браузер понимает, что это одна группа и выбрать можно только один вариант.
- На странице Log in `name="RememberMe"` есть у двух элементов: у чекбокса и у скрытого
  `input type="hidden"`, который так создаёт ASP.NET MVC. `find_element` вернёт первый,
  то есть чекбокс, а `find_elements` вернёт оба. Скрипт проверяет и то, и другое.
- Мета-теги (`description`, `keywords`, `generator`, `viewport`) на экране не видны, но
  `find_element` их находит, а `get_attribute("content")` читает их значение.
  У `description` на этом сайте `content` пустой, поэтому в выводе пустая строка.

### Какую стратегию выбирать

Порядок по надёжности и скорости: **ID → NAME → CSS (класс или атрибут) → XPath**.
XPath самый гибкий (поиск по тексту, переход к родителю), но длинные абсолютные пути вроде
`/html/body/div[4]/div[1]/...` ломаются от любой правки вёрстки. Такие пути лучше не использовать.

### Явное ожидание

```python
wait = WebDriverWait(driver, 10)
wait.until(EC.presence_of_element_located((By.ID, "small-searchterms")))
```

`WebDriverWait` каждые 0.5 с проверяет условие, максимум 10 с. Если условие не выполнилось,
бросает `TimeoutException`. Обрати внимание на **двойные скобки**: условию передаётся
кортеж `(By.ID, "...")`. `presence_of_element_located` значит, что элемент есть в DOM.
`visibility_of_element_located` значит, что элемент ещё и виден: на странице входа мы ждём,
пока поле Email станет видимым.

### Типичные ошибки

- `By.CLASS_NAME` с несколькими классами через пробел.
- `@class='один-класс'` в XPath, когда классов у элемента несколько.
- Индекс `[0]` в XPath: нумерация начинается с 1.
- Ожидать от `find_elements` исключение: он молча вернёт `[]`, поэтому проверяй `len()`.
- Сравнивать `text()` в XPath с тем, что видно на экране после CSS-преобразований.
