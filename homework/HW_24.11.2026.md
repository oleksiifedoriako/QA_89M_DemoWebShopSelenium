## Подробное объяснение

### Общая структура скрипта

1. `webdriver.Chrome()` запускает браузер.
2. `driver.get(URL)` открывает сайт и ждёт загрузки страницы, а `maximize_window()` разворачивает окно,
   чтобы вёрстка была десктопной.
3. Для каждого тега выполняются два поиска: по имени тега и CSS-селектором.
4. Проверки (`assert`): обе стратегии должны найти **одно и то же**.
5. `finally: driver.quit()` закрывает браузер всегда, даже если что-то упало.

### By.TAG_NAME

Ищет элементы по имени HTML-тега:

```python
div = driver.find_element(By.TAG_NAME, "div")
```

Тег почти никогда не уникален: на главной 95 ссылок `a` и 77 пунктов `li`.
Поэтому `By.TAG_NAME` удобен в двух случаях:

- нужно **посчитать** или перебрать все элементы одного типа (`find_elements` + `len()`);
- нужно искать **внутри** уже найденного элемента, например
  `header_logo.find_element(By.TAG_NAME, "img")`.

Для поиска конкретной кнопки или поля он не подходит: `find_element` вернёт первый тег этого
типа на странице, а это может быть совсем не тот элемент, который нужен.

### By.CSS_SELECTOR

CSS-селектор — тот же язык, которым пишутся стили сайта. Самый простой селектор — **селектор
типа**, то есть просто имя тега: `"div"`, `"a"`, `"h2"`. Он находит ровно те же элементы, что и
`By.TAG_NAME`. Кстати, внутри Selenium 4 `By.TAG_NAME` тоже превращается в CSS-запрос.

Сила CSS видна, когда селектор уточняют:

| Селектор | Что найдёт |
|---|---|
| `div` | все `div` |
| `.header-logo` | элементы с классом `header-logo` |
| `#small-searchterms` | элемент с id `small-searchterms` |
| `input[type='text']` | `input` с атрибутом `type="text"` |
| `.header-links a` | все `a` внутри `.header-links` (на любой глубине) |
| `ul > li` | `li`, которые прямые потомки `ul` |
| `li:first-child` | первый `li` в своём списке |

ID, классы и атрибуты подробно разобраны в следующем ДЗ: [HW_25.11.2026.md](HW_25.11.2026.md).

### `find_element` и `find_elements`

- `find_element(...)` возвращает **первый** подходящий элемент. Если ничего не найдено,
  бросает `NoSuchElementException`.
- `find_elements(...)` возвращает **список**, а если ничего нет, то пустой список `[]` без ошибки.

Поэтому для одиночных тегов (`div`, `ul`, `form`…) скрипт сравнивает сами элементы,
а для множественных (`a`, `li`, `img`, `h2`, `h3`) сравнивает количество через `len()`.

### Как работают проверки

```python
assert div == div_1
assert len(a_list) == len(a_list_1)
```

Два `WebElement` равны через `==`, если указывают на один и тот же узел DOM:
Selenium сравнивает их внутренний id в браузере. Если хоть одна проверка не проходит,
возникает `AssertionError`, скрипт останавливается, а `finally` всё равно закрывает браузер.

### `.text` и HTML

`strong.text` вернул `CATEGORIES` заглавными буквами, хотя в HTML написано `Categories`.
`.text` возвращает текст так, как он **виден на экране**, а сайт делает его заглавным через CSS
(`text-transform: uppercase`). Если сравнивать с текстом из HTML, проверка упадёт.

### `try/finally` и `quit()`

- `finally` выполняется при любом исходе, поэтому не остаются висеть окна Chrome и процессы chromedriver.
- `quit()` закрывает все окна и завершает сессию драйвера, а `close()` закрыл бы только текущую вкладку.

### Типичные ошибки

- Ждать от `find_elements` исключение: он молча вернёт `[]`, поэтому проверяй `len()`.
- Использовать `By.TAG_NAME` для конкретного элемента: найдётся первый попавшийся тег, а не нужный.
- Писать в CSS `.div` или `#div` вместо `div`: точка означает класс, решётка означает id.
- Сравнивать `.text` с HTML-текстом без учёта CSS-преобразований.
- Забыть `driver.quit()`: браузеры и драйверы копятся в памяти.
